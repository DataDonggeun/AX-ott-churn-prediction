# CRM Full Workbench 검증 보고서

## 확인한 것

- `app_crm_full_workbench.py`는 Python 문법 검사와 AST 파싱을 통과했습니다.
- Streamlit UI 호출을 모사한 stub 실행으로 10개 메뉴 분기 모두 예외 없이 실행되는지 확인했습니다.
- 공식 입력 `06x_expanded_dataset.csv`는 23,097행 × 82열입니다.
- 프로모션 구독 이벤트는 11,904건입니다.
- hard gate 제거 S1~S6 기준은 앱 내부 계산과 `validation_outputs/canonical_segment_summary_promotion.csv`로 재현됩니다.
- 기존 hard gate를 적용하면 2,429건, 20.40%가 다른 메인 상태군으로 이동합니다.

## W4 연결 상태

앱은 구독 이벤트와 원천 시청 이력을 다음 기준으로 연결합니다.

- 프로모션 여부, 재구매 결과, 본인인증 상태가 같은 `Membership_v2` 행의 `reg_date` 사용
- `USER_KEY → USER_NUM → View_History_v2` 연결
- W4는 Day 21~27 시청 합계
- USER_NUM 후보가 여럿이면 후보별 W4 합계가 동일한 경우에만 해석

현재 재계산 결과:

| 항목 | 값 |
|---|---:|
| 프로모션 이벤트 | 11,904건 |
| 다중 USER_NUM 후보 이벤트 | 2건 |
| 후보별 W4 결과 충돌 이벤트 | 0건 |
| W4 시청 있음 이벤트 | 3,003건 |

Claude review의 W4 시청 있음 집계는 3,005건이므로 2건 차이가 남습니다. 원인이 합의되기 전까지 앱은 W4를 `내부 재구성 관측값`으로만 표시합니다.

## 제외한 오류 요소

- C0~C3 K-Means 군집 중심 해석
- 난수 기반 이탈 점수
- 원천 근거 없는 모델 성능·SHAP·LTV·기대매출
- 작품·장르 재구매율을 CRM 트리거로 사용하는 주장
- W4 시청을 CRM 효과로 단정하는 문장
- 출처 검증되지 않은 외부 효과 수치

## 확인하지 못한 것

- 실제 Streamlit 브라우저 렌더링: 이 실행 환경에서 Streamlit 설치가 완료되지 않아 브라우저 구동 검증은 수행하지 못했습니다.
- Gemini API 실제 호출: 실제 API 키를 받거나 저장하지 않았으며 호출하지 않았습니다.
- 팀원 기존 프로젝트 폴더와의 병합: 전체 Streamlit 프로젝트 폴더를 아직 받지 않았으므로 독립 후보본으로만 제작했습니다.
