## 0. 특성공학(Feature Engineering)이란?

안녕하세요, 저는 오늘 4장 데이터 표현과 특성공학 파트를 발표하겠습니다.

먼저 특성공학이 뭔지부터 시작하겠습니다.

쉽게 말하면 **데이터를 모델에 넣기 전에 어떻게 표현하느냐**의 문제입니다. 같은 데이터라도 표현 방법에 따라 모델 성능이 완전히 달라질 수 있어요.

예를 들어 나이라는 숫자를 그냥 넣는 것과, 10대/20대/30대로 나눠서 넣는 것, 두 가지는 완전히 다른 정보를 모델에 주는 겁니다.

이번 장에서 배울 내용은 범주형 변수를 어떻게 숫자로 바꾸는지, 구간 분할, 피처 조합, 수학 함수 변환, 그리고 중요한 피처만 골라내는 특성 선택까지입니다.

## 1. 범주형 변수 — 원-핫 인코딩
> pp. 288 – 301

첫 번째는 범주형 변수 처리입니다.

먼저 범주형 변수란 무엇일까요? 범주형 변수는 성별, 혈액형처럼 항목을 분류하는 질적 데이터를 말합니다.

머신러닝 모델은 숫자만 다룰 수 있습니다. 그래서 "서울", "부산", "대구" 같은 문자열 변수를 반드시 숫자로 바꿔야 합니다.

여기서 가장 단순한 방법이 "서울=1, 부산=2, 대구=3"처럼 그냥 숫자를 매핑하는 건데요, 이게 왜 안 되냐면, 모델 입장에서는 **대구(3) > 부산(2) > 서울(1)** 이라는 순서가 있다고 잘못 학습하기 때문입니다. 세 도시 사이에 크기 관계 같은 건 없는데 숫자를 넣으면 그렇게 인식해버립니다.

그래서 쓰는 게 **원-핫 인코딩**입니다.

*(화면 가리키며)* 이 그림처럼 각 범주를 별도의 0/1 컬럼으로 만듭니다. 서울이면 서울 컬럼만 1이고 나머지는 0, 부산이면 부산 컬럼만 1이 되는 방식입니다. 이렇게 하면 범주 간에 순서 관계가 생기지 않습니다.

코드는 pandas의 `get_dummies`나 sklearn의 `OneHotEncoder` 두 가지 방법이 있는데요, Pipeline 안에서 쓸 때는 sklearn 방법을 씁니다.

실전에서 반드시 챙겨야 하는 옵션이 하나 있습니다. **`handle_unknown='ignore'`** 인데요, 학습 데이터에 없던 범주가 테스트 데이터에 나타날 수 있거든요. 이 옵션을 주면 모르는 범주를 모두 0으로 처리해서 오류를 방지합니다.

그리고 "낮음/보통/높음"처럼 **순서가 있는 범주형**은 `OrdinalEncoder`를 씁니다. 0, 1, 2로 매핑해도 의미가 맞고, 컬럼 수도 늘어나지 않아서 효율적입니다.

그럼 이게 labelEncoder라고 생각을 할 수있는데요? sklearn에서는 y를 기준으로 하면 labelEncoder x값을 기준으로 하면 OrifinalEncoder라고 합니다.

## 2. 구간 분할 (Binning / Discretization)
> pp. 301 – 308

두 번째는 구간 분할입니다.

나이 27.5세를 "20대"로 바꾸는 것처럼, 연속적인 숫자를 구간으로 나누는 방법입니다.

왜 이렇게 하냐면, **선형 모델은 직선밖에 못 그립니다.** 예를 들어 나이와 ott 구매율 사이에 "20대와 30대는 구매율이 높고, 나머지 나잇대는 높다"는 비선형 패턴이 있다고 해봅시다. 연속값 그대로 넣으면 선형 모델은 이 패턴을 직선 하나로밖에 표현 못 합니다. 그런데 구간으로 나누면 각 구간마다 별도의 계수를 학습할 수 있어서 비선형 패턴을 표현할 수 있게 됩니다.

여기서 중요한 게 있는데요, **트리 기반 모델에는 구간 분할이 필요 없습니다.** 랜덤 포레스트나 그래디언트 부스팅은 스스로 최적의 구간을 찾거든요. 미리 나눠줘봤자 효과가 없거나 오히려 정보 손실이 생깁니다.

코드는 `KBinsDiscretizer`를 사용하고, strategy 옵션으로 구간 방식을 정합니다. `uniform`은 동일 너비, `quantile`은 동일 샘플 수, `kmeans`는 k-평균 방식입니다.

그리고 구간 분할을 더 강력하게 쓰는 방법이 있는데요, **구간 분할 + 상호작용 조합**입니다. 구간으로 나눈 피처에 원본 특성을 곱하면, 각 구간마다 다른 기울기를 학습할 수 있습니다. 선형 모델도 결정 트리처럼 동작하게 되는 효과가 있습니다.

## 3. ColumnTransformer — 피처마다 다른 전처리
> pp. 295 – 301

세 번째는 ColumnTransformer입니다.

실제 데이터에는 수치형 컬럼과 범주형 컬럼이 섞여 있습니다. 수치형은 StandardScaler로 정규화하고, 범주형은 OneHotEncoder로 변환해야 하는데, 이걸 따로따로 하면 코드가 복잡해지고 실수하기도 쉽습니다.

*(화면 가리키며)* `ColumnTransformer`가 이 문제를 해결합니다. 컬럼마다 다른 변환기를 지정하면 알아서 각각 적용하고, 결과를 하나의 배열로 합쳐줍니다.

사용 방법은 두 가지입니다. `ColumnTransformer`를 직접 쓰거나, 더 간결한 `make_column_transformer`를 씁니다. 컬럼이 50개면 하나하나 적기 너무 귀찮은데, make 버전은 이름 자동 지정에 코드도 짧아집니다.

주의할 점이 하나 있습니다. 지정하지 않은 컬럼은 기본적으로 **버려집니다.** 남기고 싶은 컬럼이 있으면 `remainder='passthrough'`로 설정해야 합니다.

그리고 ColumnTransformer는 **Pipeline과 함께 쓰는 게 실전 패턴**입니다. 전처리기와 모델을 Pipeline으로 묶으면, 테스트 데이터에 실수로 fit을 하는 데이터 누수 문제도 방지됩니다.

## 4. 상호작용과 다항식 특성
> pp. 308 – 312

네 번째는 상호작용과 다항식입니다.

두 피처를 곱하거나 제곱해서 새로운 피처를 만드는 방법입니다.

**상호작용 특성**은 A × B처럼 두 피처를 곱한 겁니다. 예를 들어 나이와 소득을 곱하면 "나이도 높고 소득도 높은 경우"를 따로 학습할 수 있습니다. 두 변수가 따로따로가 아니라 **함께 작용할 때** 유용합니다.

**다항식 특성**은 x → x, x², x³처럼 제곱, 세제곱을 추가합니다. 이렇게 하면 선형 모델이 곡선을 학습할 수 있게 됩니다. sklearn의 `PolynomialFeatures`가 이 역할을 해줍니다.

단점이 하나 있는데요, 피처 수가 **폭발적으로 늘어납니다.** n개 피처에서 상호작용을 만들면 n(n+1)/2개가 생깁니다. 피처가 100개면 5,050개가 되죠. 
그래서 뒤에 나올 특성 선택 방법과 반드시 함께 써야 합니다.

다항식 특성을 직접 만들지 않고도 **커널 SVM**을 사용하면 비슷한 복잡도의 예측을 만들 수 있습니다. 커널 SVM은 내부적으로 고차원 변환을 수행해서 특성을 직접 만들 필요가 없는데요, 대신 해석이 어렵고 데이터가 많으면 느려지는 단점이 있습니다.


커널 SVM에 대해서 잘 이해가 되시나요????
SVM은 두 클래스를 가장 널읍 여백(마진)으로 나누는 경계선을 찾는 모델입니다. 
그럼 왜 마진을 최대화 하냐고 하면은 경계선이 두 클래스에서 최대한 멀리 떨어질수록 새로운 데이터에도 잘 맞기 때문이다.

그래서 다시 돌아와 커널 SVM은 직선으로 못 나누는 데이터가 있을 때 저차원을 고차원으로 올려서 나눌 수 있게 만드는 것입니다.

## 4+. 수학 함수 변환 — log / exp / sin
> pp. 312 – 315

제곱·세제곱 외에도 log, exp(자연상수), sin 같은 수학 함수를 특성에 적용하는 방법도 있습니다.

특히 사용자 로그인 횟수나 시청 횟수처럼 **정수이고 음수가 없는 카운트 데이터**는 오른쪽으로 치우친 분포를 가집니다. 이런 데이터에 Ridge 같은 선형 모델을 그냥 쓰면 R²가 매우 낮게 나옵니다.

여기에 **log 변환**을 적용하면 분포가 정규분포에 가까워지면서 성능이 크게 올라갑니다. 주의할 점은 데이터에 0이 있으면 log(0)이 정의가 안 되므로 `log(X+1)`을 사용해야 한다는 것입니다.

트리 기반 모델은 특성의 순서에만 영향받기 때문에 log 변환을 해도 결과가 거의 같습니다. 변환이 효과적인 건 주로 **선형 모델, SVM, 신경망**입니다.

마지막으로 **외삽(Extrapolation)** 얘기를 잠깐 하겠습니다. 랜덤 포레스트 같은 트리 모델은 훈련 데이터 범위 밖의 값을 예측하지 못합니다. 범위 밖에서는 마지막으로 본 값을 그대로 반복하기 때문에 예측이 수평선처럼 나옵니다. 시계열 데이터처럼 미래를 예측해야 하는 경우에는 이 한계를 반드시 고려해야 합니다.

저희 프로젝트는 제가 알기로는 미래시점을 예측하는 것보다는 재결제 또는 이탈을 했는지 안했는지 분류를 하는것을 목표로 하고 있는데 그러면 저희는 분류이기 때문에 와삽이 발생하지는 않습니다. 다행이죠 하지만 혹시나 모르니 조금있다가 멘토님이랑 같이 애기를 해보는게 좋을 것 같습니다.

## 5. 특성 자동 선택 — 일변량 통계
> pp. 315 – 318

다섯 번째부터는 특성 선택입니다. 만들어진 피처 중에 필요 없는 것을 골라내는 방법입니다.

피처가 많다고 무조건 좋은 게 아닙니다. 불필요한 피처를 제거하면 모델이 더 단순해지고 과적합이 줄어듭니다.

가장 기본적인 방법이 **일변량 통계**입니다. 각 피처와 타겟 사이의 통계적 관계를 계산해서 관계가 없는 피처를 버리는 방식인데요, 각 피처를 **독립적으로** 평가한다는 점이 특징입니다.

코드는 `SelectPercentile`이나 `SelectKBest`를 씁니다. `score_func=f_classif`로 분류 문제에 맞는 통계 방법을 지정합니다. 상위 50%만 남기거나, 상위 k개만 남기는 방식으로 씁니다.

장점은 계산이 매우 빠르다는 겁니다. 피처가 엄청 많을 때 1차 필터링으로 쓰기 좋습니다.

단점은 피처 간 상호작용을 전혀 고려하지 않는다는 겁니다. 단독으로는 별로인데 다른 피처와 조합하면 강력한 피처가 있을 수 있는데, 그런 걸 놓칠 수 있습니다.

## 6. 모델 기반 특성 선택
> pp. 318 – 322

여섯 번째는 모델 기반 특성 선택입니다.

일변량 통계의 단점을 보완합니다. 지도 학습 모델을 사용해서 피처 중요도를 계산하고 중요하지 않은 피처를 제거하는 방법으로, **피처 간 관계를 고려**한다는 점이 다릅니다.

선형 모델을 쓰면 계수의 절댓값이 작은 피처를 제거합니다. 특히 L1 규제(Lasso)를 쓰면 불필요한 피처의 계수가 아예 0이 되어버려서 자동으로 선택됩니다.

트리 기반 모델을 쓰면 `feature_importances_`로 피처 중요도를 계산합니다. sklearn에서는 `SelectFromModel`이라는 래퍼를 제공해서, 어떤 모델이든 여기에 넣으면 특성 선택기로 바꿔줍니다.

한 가지 알아둘 게 있는데요, **특성 선택에 쓰는 모델과 최종 예측 모델이 같을 필요가 없습니다.** 랜덤 포레스트로 중요도를 계산해서 피처를 고르고, 실제 예측은 로지스틱 회귀를 쓸 수 있습니다. 특성 선택용 모델은 그냥 중요도를 계산하는 도구입니다.

## 7. 반복적 특성 선택 — RFE
> pp. 322 – 325

일곱 번째는 RFE입니다. Recursive Feature Elimination의 약자입니다.

세 가지 특성 선택 방법 중 **가장 정밀하지만 가장 느린** 방법입니다.

동작 방식은 이렇습니다.

1. 전체 피처로 모델을 학습하고 각 피처의 중요도를 계산합니다.
2. 중요도가 가장 낮은 피처를 하나 제거합니다.
3. 원하는 피처 수가 남을 때까지 반복합니다.

한 번에 다 제거하는 게 아니라 하나씩 제거하면서 매번 재평가하기 때문에 시간이 오래 걸리는 대신 더 정확한 선택을 합니다.

*(화면 가리키며)* 세 방법을 비교하면 이렇습니다. 일변량 통계는 매우 빠르지만 피처 간 관계를 못 봅니다. 모델 기반은 속도와 정확도의 균형이 좋아서 일반적인 상황에서 권장합니다. RFE는 느리지만 가장 정밀한 선택이 필요할 때 씁니다.

## 8. 전문가 지식 활용 — 스팀 게임 예제
> pp. 325 – 337

마지막으로 전문가 지식 활용입니다.
전문가 지식 활용은 알고리즘이 자동으로 찾기 어려운 패턴을 사람이 직접 피처로 만들어주는 방법인데요

예시를 보겠습니다. 원래 책에서는 시티바이크 자전거 대여 데이터로 예제를 진행했는데요, 이게 생각보다 어려울뿐더러 이해를 시킬 자신이 없어서 저희가 해봤던 스팀 프로젝트로 예시를 들어서 설명하겠습니다.


저희가 그때는 할인율에 따른 동시접속자를 예측을 해보았는데요 이번에는 게임 평점이나 구매 여부를 예측한다고 해봅시다. 원본 데이터에는 이런 숫자들만 있습니다.

```
용량: 45000 (MB)
출시일: 20231105
가격: 29900
장르코드: 3
```

이 숫자만 봐서는 모델이 **"이 게임이 AAA급 대작인지, 인디 게임인지"** 를 알기 어렵습니다.

여기서 전문가 지식이 들어갑니다.

**용량**만 봐도 힌트가 있어요. 45GB짜리 게임은 보통 그래픽이 좋은 대작이고, 500MB짜리는 인디 게임일 가능성이 높습니다. 그냥 숫자로 두지 말고 **"대용량 여부"** 피처로 만들 수 있어요.

```python
df['is_AAA'] = (df['용량'] >= 30000).astype(int)
```

**출시일**도 마찬가지예요. 20231105라는 숫자 하나로는 모델이 아무것도 모릅니다. 근데 게임은 **연말 시즌(11~12월)** 에 출시하면 판매량이 높고, 스팀 세일 기간에 가격이 내려가는 패턴이 있거든요.

```python
df['is_holiday_season'] = df['출시월'].isin([11, 12]).astype(int)
df['game_age_days'] = (오늘날짜 - df['출시일']).days
```

**장르코드**도 단순 숫자 3보다, RPG인지 FPS인지를 원-핫으로 나누면 훨씬 강력합니다.

그리고 게임에서도 **주기성**이 있어요. 스팀 정기 세일이 1년에 여러 번 반복되거든요. 출시 후 몇 개월째인지를 sin/cos로 표현하면 "세일 직전 출시 게임이 세일 때 판매 급등"하는 패턴을 잡을 수 있습니다.

결국 핵심 메시지는 이겁니다. **"용량=45000보다 AAA 대작, 연말 출시, RPG 장르라는 정보가 모델에게 훨씬 강력하다."** 데이터를 많이 모으는 것보다 올바른 피처를 만드는 것이 더 중요할 때도 있습니다.

## 마무리 정리

*(슬라이드 보며)* 정리하겠습니다.

| 섹션 | 핵심 요약 |
|---|---|
| **원-핫 인코딩** | 순서 없는 범주형은 반드시 원-핫으로. 숫자 직접 매핑하면 잘못된 순서 관계를 학습한다. |
| **구간 분할** | 선형 모델의 표현력 향상에 유용. 트리 모델에는 불필요. |
| **ColumnTransformer** | 수치형/범주형 혼재 데이터의 실전 패턴. Pipeline과 함께 써서 데이터 누수 방지. |
| **상호작용/다항식** | 피처 조합으로 표현력 향상. 피처 수 폭발 주의, 특성 선택과 함께 사용. |
| **log/exp(자연상수) 변환** | 카운트 데이터에 효과적. 선형 모델·SVM·신경망에 도움. 트리 모델은 변환 불필요. |
| **특성 선택 3단계** | 일변량 통계(빠름) → 모델 기반(권장) → RFE(정밀). 상황에 따라 선택. |
| **전문가 지식** | 도메인을 알면 알고리즘보다 강력한 피처를 만들 수 있음. |

이상으로 발표를 마치겠습니다. 질문 있으시면 받겠습니다.
